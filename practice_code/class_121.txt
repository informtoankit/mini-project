GitHub Actions Runners

GitHub Actions me Runner wo machine hoti hai jo workflow ke jobs ko actually execute karti hai. Jab developer code GitHub repository me push karta hai aur workflow trigger hota hai, to workflow ke saare steps (build, test, Docker image creation, deployment, etc.) kisi machine par run hote hain. Isi machine ko Runner kaha jata hai.

Simple words me:

Developer Pushes Code
          ↓
GitHub Actions Workflow Trigger
          ↓
Runner Executes Jobs
          ↓
Build → Test → Deploy
Types of GitHub Actions Runners

GitHub Actions me mainly 2 types ke runners hote hain:

1. GitHub Hosted Runner
2. Self Hosted Runner
1. GitHub Hosted Runner

GitHub Hosted Runners virtual machines hoti hain jo GitHub provide aur manage karta hai. Jab workflow trigger hota hai, GitHub automatically ek fresh VM create karta hai aur workflow us machine par run karta hai.

Features
Managed by GitHub
No infrastructure management
Auto updates
Auto security patching
Clean environment for every run
Fast setup

Supported Operating Systems:

Ubuntu Linux
Windows
macOS

Example:

runs-on: ubuntu-latest

Workflow run hone par GitHub temporary Ubuntu VM create karega.

GitHub Hosted Runner Flow

    ↓
Workflow Trigger
    ↓

    ↓
Build
    ↓
Test
    ↓
Deploy
    ↓
VM Destroyed
Important Point

Har workflow run ke liye GitHub ek fresh VM provide karta hai.

Iska matlab:

Run #1
   ↓
Fresh VM
   ↓
Destroyed

Run #2
   ↓
New Fresh VM
   ↓
Destroyed

Previous run ka data next run me available nahi hota.

2. Self Hosted Runner

Self Hosted Runner wo machine hoti hai jo tum khud manage karte ho.

Ye machine ho sakti hai:

EC2 Instance
Physical Server
VM
Kubernetes Pod
On-Prem Server

GitHub sirf workflow bhejta hai.

Execution tumhari machine par hota hai.

Self Hosted Runner Flow
Code Push
    ↓
Workflow Trigger
    ↓
GitHub Sends Job
    ↓
Your EC2 Runner
    ↓
Build
    ↓
Test
    ↓
Deploy
Benefits
Full control
Custom software
Custom hardware
Private network access
Better for enterprise workloads

Example:

runs-on: self-hosted
Why Self Hosted Runner?

Suppose application deploy karni hai EKS cluster me.

GitHub
   ↓
Private VPC
   ↓
EKS Cluster

GitHub Hosted Runner private VPC access nahi kar sakta.

Solution:

GitHub
   ↓
Self Hosted Runner (EC2)
   ↓
Private EKS Cluster

Ab deployment possible ho jayega.

Interview Question
What is a GitHub Actions Runner?

A GitHub Actions Runner is a machine that executes jobs defined in a GitHub Actions workflow. It can be either a GitHub-hosted runner managed by GitHub or a self-hosted runner managed by the organization.

Difference Between GitHub Hosted and Self Hosted Runner
GitHub Hosted	Self Hosted
Managed by GitHub	Managed by User
Temporary VM	Persistent Machine
Auto Updates	Manual Updates
Limited Customization	Full Customization
Easy Setup	Requires Management
Public Infrastructure	Private Infrastructure
Most Common Interview Answer

A Runner is the execution environment where GitHub Actions workflows run. GitHub-hosted runners are temporary VMs managed by GitHub, while self-hosted runners are user-managed machines that provide greater control and access to private infrastructure.

name: First Workflow

Easy Explanation

push              → Workflow runs when code is pushed to GitHub.

fork              → Trigger when someone forks the repository.

watch             → Trigger when someone stars (⭐) the repository.

pull_request      → Runs when a Pull Request (PR) is created or updated.

issues            → Runs when an issue is opened, closed, or modified.

discussion        → Runs when a GitHub Discussion is created or updated.

create            → Runs when a new branch or tag is created.

workflow_dispatch → Manual trigger (Run Workflow button in GitHub UI).

schedule          → Run workflow automatically at a fixed time using cron schedule.

workflow_call     → Allows one workflow to call another workflow.

One-Line Explanation of Each Line

name: First Workflow
→ Name of the workflow displayed in the GitHub Actions tab.

on: push
→ Trigger the workflow whenever code is pushed.

jobs:
→ Container that holds all jobs.

first-job:
→ Name/ID of the first job.

runs-on: ubuntu-latest
→ Run the job on a GitHub-hosted Ubuntu runner.

steps:
→ List of tasks to execute.

- name: Print Greeting
→ Human-readable name of the step.

run: echo "Hello Mica Mica"
→ Execute shell command and print message.

- name: Print Goodbye
→ Second step name.

run: echo "Done!! - bye!!"
→ Execute shell command and print final message.

Important Terms

→ Complete automation process.

Event
→ Action that triggers a workflow.

Job
→ Group of related tasks.

Step
→ Single command or action inside a job.

Runner
→ Machine that executes the job.

Action
→ Reusable automation component.

name: NodeJS CI/CD Pipeline              # Name of the workflow shown in the GitHub Actions tab

on:
  push:                                  # Automatically run the workflow whenever code is pushed to the repository
  workflow_dispatch:                     # Allow users to manually start the workflow from GitHub UI

jobs:

  test:                                  # First job responsible for validating the application

    runs-on: ubuntu-latest               # Create a fresh Ubuntu virtual machine (runner)

    steps:

      - name: Get Code                   # Download the latest source code from GitHub
        uses: actions/checkout@v4        # Official GitHub action used to checkout repository code

      - name: Install NodeJS             # Prepare NodeJS runtime environment
        uses: actions/setup-node@v4      # Official GitHub action to install NodeJS
        with:
          node-version: 18               # Install NodeJS version 18

      - name: Install Dependencies       # Download all packages required by the application
        run: npm ci                      # Install dependencies using package-lock.json

      - name: Run Tests                  # Execute automated test cases
        run: npm test                    # Verify application works correctly

  deploy:                                # Second job responsible for deployment

    needs: test                          # Run this job only if the test job succeeds

    runs-on: ubuntu-latest               # Create another fresh Ubuntu runner

    steps:

      - name: Get Code                   # Download source code again on the new runner
        uses: actions/checkout@v4        # Checkout repository code

      - name: Install NodeJS             # Install NodeJS on the deployment runner
        uses: actions/setup-node@v4      # Setup NodeJS environment
        with:
          node-version: 18               # Use NodeJS version 18

      - name: Install Dependencies       # Install application dependencies
        run: npm ci                      # Ensure all required packages are available

      - name: Build Project              # Create a production-ready application build
        run: npm run build               # Generate optimized build artifacts

      - name: Deploy                     # Deployment step
        run: echo "Deploying Application..."  # Placeholder deployment command
